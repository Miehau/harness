Operating agreements

  • One durable task shared by both supervisor entry points; retrying a handoff must not duplicate work.
  • Hosting provider and project/target settings live in .runner/project.json, editable after onboarding. Existing tasks keep their snapshotted destination.
  • Use the existing GrokBot webhook contract. Actual screenshot rendering and replies require a live receiver check.
  • Preserve runner ownership of questions, artifacts, integration, final verification and merge approval.
  • Trusted local execution is the approved fallback. Reuse existing isolation only if it protects the whole execution path without a major new subsystem.

Verification & tracking

  • Every task records implementation, checks and evidence before it becomes verified.
  • Mocked tests cover both GitHub and GitLab, errors, retries and stale approvals. They make no model calls.
  • Live probes validate OMP/Herdr without model calls. A separately recorded end-to-end canary validates the model-driven flow.
  • External checks remain unverified if credentials, receiver or a test project are unavailable; no inferred pass.
  • This file is the tracker. I update statuses, evidence and the activity log after each implementation batch; reload to see updates.
